# A01.2 — Fundament testów jednostkowych i UI

**Milestone:** A — Fundament  
**Epic:** A01 — Konfiguracja aplikacji  
**Story / rezultat:** Gotowy, uruchamialny zestaw testów dla Expo/React Native, z przykładowym testem ekranu `Hello World` oraz bazą pod przyszłe testy logiki finansowej.  
**Status:** Backlog  
**Zależności:** A01.1  
**Interactive Planning Gate:** required  
**Powiązane dokumenty:** `AGENTS.md`, `PROGRESS.md`, `docs/06-architecture.md`, `docs/07-acceptance-tests.md`, `docs/10-agent-workflow.md`, `docs/12-implementation-decisions.md`, `skills/interactive-planning/SKILL.md`

## Przed implementacją — wymagana interaktywna ankieta
- Sprawdź faktycznie zainstalowane wersje Expo, React Native i TypeScript.
- Zapytaj o preferencje dotyczące Jest + jest-expo, React Native Testing Library, organizacji testów, mocków natywnych modułów, code coverage oraz czy E2E (np. Maestro) konfigurujemy teraz czy odkładamy.
- Zaproponuj stabilny, kompatybilny zestaw, nie instaluj alternatywnych frameworków jednocześnie bez zgody.
- Pokaż plan i poczekaj na akceptację **przed** instalacją pakietów i zmianą konfiguracji.

## Scope
- Konfiguracja uzgodnionego test runnera i bibliotek testów komponentowych oraz niezbędnych mocków.
- Test renderowania `Hello World` i jego dostępności/treści, jeden prosty przykład czystego testu jednostkowego (bez wymyślania finansowych funkcji produkcyjnych).
- Skrypty `test`, ewentualnie `test:watch`, konfiguracja raportowania i krótka instrukcja uruchomienia.
- Potwierdzenie kompatybilności z faktyczną konfiguracją Expo/NativeWind/Blur; minimalne mocki tylko tam, gdzie są potrzebne.

## Out of scope
- Implementacja nowych ekranów, logiki finansowej i SQLite; pełny zestaw testów domenowych.
- Testy E2E i natywna konfiguracja symulatorów, o ile użytkownik jawnie nie zatwierdzi osobnego małego rozszerzenia albo nowego taska.
- Ciężka infrastruktura CI/CD i rozbudowane raportowanie bez uzasadnienia.

## Acceptance criteria
- [ ] Ankieta zakończona, plan testowej infrastruktury zatwierdzony przez użytkownika.
- [ ] `test` i typecheck działają na aktualnych zależnościach projektu.
- [ ] Test komponentowy potwierdza wyświetlenie `Hello World`.
- [ ] Przykładowy test jednostkowy działa, bez tworzenia fałszywej logiki domenowej.
- [ ] README lub dokument testowy opisuje uruchomienie i ograniczenia.
- [ ] W raporcie nie deklaruje się wykonania E2E, jeżeli faktycznie nie zostało wykonane.
